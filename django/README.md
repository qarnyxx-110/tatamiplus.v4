# طراحی تاتامی پلاس برای تمپلیت‌های Django

این پوشه طراحی جدید تاتامی پلاس (سیستم طراحی تیره قرمز و مشکی، فونت‌های Lalezar و Vazirmatn) را به‌شکل تمپلیت‌ها و فایل‌های استاتیک پروژهٔ Django مخزن [`Tatami-demo`](https://github.com/Radinsharifi/Tatami-demo) آماده کرده است. مسیر فایل‌ها دقیقاً همان مسیرهای آن پروژه است.

**هیچ تغییری در کد پایتون لازم نیست.** نام تمپلیت‌ها، نام مسیرها (`{% url %}`)، متغیرهای context هر view، فیلدهای فرم و تگ‌های `store_format`، `persian` و `jformat` همان‌هایی است که در بک‌اند وجود دارد.

## نصب

از ریشهٔ همین مخزن:

```bash
cp -R django/templates/. ../Tatami-demo/templates/
cp -R django/static/.    ../Tatami-demo/static/
```

بعد در پروژهٔ Django:

```bash
python manage.py check
python manage.py test
python manage.py runserver
```

فایل قدیمی `static/css/styles.css` دیگر استفاده نمی‌شود و می‌توانید آن را حذف کنید.

## چه چیزهایی جایگزین می‌شود

| فایل | توضیح |
|---|---|
| `templates/base.html` | هدر (منوی اصلی، سبد، حساب، منوی کشویی موبایل)، پیام‌های `messages`، فوتر. خروج همچنان فرم POST با `{% csrf_token %}` است. |
| `templates/includes/form_fields.html` | **جدید.** رندر یکسان همهٔ فرم‌ها: برچسب، «اختیاری»، راهنما با شناسهٔ `{{ field.auto_id }}_helptext` (همان که Django در `aria-describedby` می‌گذارد)، خطای هر فیلد و خطاهای کلی فرم. |
| `templates/pages/home.html`، `account.html` | خانه و حساب کاربری. حساب مربی مراحل «ثبت درخواست ← بررسی ← انتشار» را با `user.coach_application` نشان می‌دهد. |
| `templates/accounts/login.html`، `register.html` | ورود و ثبت‌نام. `next` حفظ می‌شود. |
| `templates/coaches/*.html` | فهرست، پروفایل، درخواست همکاری و وضعیت درخواست. متن «تاریخ ثبت: …» عیناً حفظ شده، چون تست `test_application_status_uses_persian_jalali_date` آن را بررسی می‌کند. |
| `templates/store/*.html` | فهرست با فیلترهای GET و صفحه‌بندی (`{% querystring %}` در Django 5.1 به بعد)، جزئیات با `AddToCartForm`، سبد با فرم‌های به‌روزرسانی و حذف. |
| `templates/403.html`، `404.html` | **جدید.** وقتی `DEBUG=False` است، Django این صفحه‌ها را خودکار نشان می‌دهد؛ مثلاً هنرجویی که `/coaches/apply/` را باز کند. |
| `static/css/tatami.css` | **ساخته‌شده؛ دستی ویرایش نکنید.** خروجی `shared/build.js` از همان توکن‌ها و CSS طراحی مشترک، به‌علاوهٔ `shared/src/css/django.css`. |
| `static/js/tatami.js` | بهبودهای کوچک: منوی کشویی، نمایش گذرواژه، متن فارسی انتخاب فایل، گزینهٔ خالی تنوع محصول، باز کردن فیلترها در موبایل، ارسال خودکار مرتب‌سازی، فوکوس روی اولین فیلد خطادار و جلوگیری از ارسال دوباره. **همهٔ صفحه‌ها بدون جاوااسکریپت هم کار می‌کنند.** |

## به‌روز نگه داشتن CSS

هر تغییری در طراحی را در `shared/src` انجام دهید و بعد:

```bash
cd shared && node build.js
```

با این دستور، `django/static/css/tatami.css` همراه بقیهٔ خروجی‌ها از نو ساخته می‌شود. قواعدی که فقط مخصوص تمپلیت‌های Django هستند در `shared/src/css/django.css` قرار دارند.

## تصمیم‌های UX که با بک‌اند هماهنگ شده‌اند

- **فقط امکانات موجود در بک‌اند** در منو و صفحه‌ها آمده‌اند: خانه، فروشگاه، سبد، مربیان، حساب، ورود و ثبت‌نام، درخواست مربیگری. بلاگ، داشبوردها، پرداخت و سفارش نیامده‌اند، چون طبق سند همکاری هنوز پیاده نشده‌اند.
- **سبد خرید** جملهٔ «ثبت سفارش و پرداخت در این مرحله فعال نیست» را نشان می‌دهد و دکمهٔ پرداخت ندارد.
- **فرم‌ها `novalidate` دارند.** اعتبارسنجی را Django انجام می‌دهد و پیام‌ها فارسی و کنار هر فیلد نمایش داده می‌شوند، نه پیام‌های انگلیسی مرورگر. Django 5 خودش `aria-invalid` را روی فیلد خطادار می‌گذارد و CSS آن را قرمز می‌کند.
- **صفحهٔ خانه** حالا «جودو» می‌گوید. متن قبلی به‌اشتباه «تکواندو» نوشته بود.

## محدودیت‌های شناخته‌شده

1. **تعداد اقلام سبد در هدر نمایش داده نمی‌شود.** برای نمایش آن، بک‌اند باید یک context processor اضافه کند که تعداد را در همهٔ صفحه‌ها در اختیار تمپلیت بگذارد.
2. **گزینهٔ خالی انتخاب تنوع** در Django برچسب `---------` دارد. فعلاً جاوااسکریپت آن را به «سایز و رنگ را انتخاب کنید» تغییر می‌دهد؛ راه تمیزتر تنظیم `empty_label` در `AddToCartForm` است.
3. **پروفایل مربی** فقط نام نمایشی، عنوان کوتاه و معرفی را دارد، چون مدل `CoachProfile` همین فیلدها را دارد. کارنامه، رتبه‌ها و مستر کلاس‌های طراحی فرانت‌اند به مدل‌های جدید نیاز دارند.
4. **تمپلیت‌ها با Django واقعی اجرا نشده‌اند.** دسترسی به PyPI در محیط ساخت نبود. به‌جای آن:
   - **بررسی ساختاری:** همهٔ تگ‌ها باز و بسته شده‌اند، هر نام `{% url %}` با `urls.py` بک‌اند و تعداد آرگومان‌هایش می‌خواند، هر فیلتر یا داخلی Django است یا از کتابخانهٔ load‌شده می‌آید، و هر متغیر همان است که view می‌فرستد.
   - **رندر آزمایشی:** همهٔ ۱۷ حالت صفحه با داده‌ی شبیه‌سازی‌شده رندر و در دسکتاپ و موبایل بررسی شد؛ بدون اسکرول افقی، کنتراست ضعیف یا هدف لمسی کوچک‌تر از ۴۴ پیکسل.

   قبل از ادغام، حتماً `python manage.py test` را اجرا کنید و صفحه‌ها را با `runserver` ببینید.
