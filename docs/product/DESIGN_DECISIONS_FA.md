# تصمیم‌های طراحی محصول و زبان بصری

**تاریخ:** ۲۸ نوامبر ۲۰۲۶  
**وضعیت:** جهت بصری منتخب ثبت شد؛ توکن‌های کد هنوز تغییر نکرده‌اند.

## ۱. مرجع بصری

مرجع بازطراحی، نمونهٔ HTML تأییدشدهٔ پروژه با فضای تیره و سینمایی است. هویت نهایی بر پایهٔ این ویژگی‌هاست:
- زغالی عمیق و مشکی نرم برای زمینه؛
- قرمز تاتامی برای اقدام اصلی و هویت ورزشی؛
- طلایی برای تأکید، رتبه/کمربند و جزئیات ممتاز؛
- تایپوگرافی فارسی با Vazirmatn و Lalezar؛
- جزئیات لاتین محدود با خانوادهٔ متناسب، بدون قربانی‌کردن خوانایی فارسی؛
- عمق و بافت کنترل‌شده، سایه‌های هدفمند و حرکت کوتاه و معنادار.

## ۲. پالت مرجع اولیه

این مقادیر، مقادیر مرجع بصری نمونه‌اند و هنوز جایگزین توکن‌های کد نشده‌اند:

| نقش | مقدار مرجع |
|---|---|
| زمینهٔ اصلی | #0c0e12 |
| سطح ثانویه | #12151b |
| سطح کارت | #171b22 |
| قرمز اصلی | #C0392B |
| قرمز روشن/hover | #E24A3B |
| طلایی اصلی | #E8B85A |
| طلایی روشن | #F6D58E |
| متن اصلی | #ECE7DF |
| متن ثانویه | #9aa0aa |

این جدول نقطهٔ شروع است، نه مجوز استفادهٔ مستقیم و بی‌بررسی از هر جفت‌رنگ. قبل از اعمال به توکن‌ها، کنتراست متن عادی، متن بزرگ، آیکون، دکمه و focus ring بررسی می‌شود. در صورت ناکافی بودن کنتراست، مقدار معنایی مناسب اصلاح می‌شود بدون اینکه هویت کلی پالت تغییر کند.

## ۳. تعارض با سیستم فعلی

DESIGN_SYSTEM.md و tokens.json فعلی از آبی جودو به‌عنوان brand و از قرمز عمدتاً برای danger استفاده می‌کنند. این با مرجع بصری منتخب بازطراحی هم‌راستا نیست.

راه‌حل:
1. ساختار فنی توکن‌ها و خروجی CSS فعلی حفظ شود.
2. رنگ‌ها در سطح نقش معنایی تعریف شوند، نه با جست‌وجو/جایگزینی پراکنده.
3. قرمز فقط به danger محدود نماند و پس از بررسی کنتراست به رنگ اصلی برند تبدیل شود.
4. طلایی رنگ تأکید باشد، نه برای متن ریز یا سطح گستردهٔ کم‌کنتراست.
5. آبی فقط در صورت نیاز عملکردی/اطلاعاتی و خارج از رقابت با هویت اصلی باقی بماند.
6. Preview، سه PWA و قالب‌های Django از یک منبع توکن هم‌زمان Build شوند.

تا زمان پایان بررسی، tokens.json فعلی دست‌نخورده می‌ماند.

## ۴. قواعد صفحه و اجزا

- همهٔ صفحات RTL-first هستند و باید در محتوای LTR از bdi یا جهت‌دهی منطقی استفاده کنند.
- از CSS logical properties استفاده شود؛ طراحی با left/right ثابت ممنوع است مگر برای asset واقعاً جهت‌دار.
- اجزای پایه مشترک‌اند، اما ترکیب و سلسله‌مراتب هر صفحه متناسب با وظیفهٔ آن است.
- صفحهٔ فروشگاه، داشبورد، ورود، دوره و پروفایل نباید یک قالب یکسان با تعویض عنوان باشند.
- حالت‌های واقعی و غیرواقعی از نظر بصری قابل تشخیص‌اند.
- برای بخش فاقد دادهٔ واقعی از empty state و توضیح استفاده شود، نه کارت با عدد/تصویر/امتیاز ساختگی.
- در موبایل، اولویت با خوانایی، لمس، جریان عمودی و حفظ سلسله‌مراتب اطلاعات است.
- فوکوس صفحه‌کلید، خطاهای فرم، disabled/loading و reduced-motion از ابتدای طراحی لحاظ شوند.

## ۵. معیار تأیید Design Tokens

پیش از تغییر فایل shared/src/design/tokens.json:
- تمام semantic tokenها و مصرف‌کنندگان فعلی فهرست شوند؛
- نسبت کنتراست با الگوریتم WCAG محاسبه و ثبت شود؛
- رنگ متن، پس‌زمینه، border، icon، focus و overlay جداگانه بررسی شوند؛
- رنگ‌های برند در CSS، Template و JS وابسته به نام توکن باشند؛
- Build هر پنج خروجی و diff فایل‌های تولیدی بررسی شود؛
- تست screenshot/visual regression در صفحات مرجع انجام شود.
