# ماتریس تضمین کیفیت طراحی و فرانت‌اند

**نسخه:** ۰.۱، ۲۸ نوامبر ۲۰۲۶  
**وضعیت جاری:** تعریف معیار؛ اجرای تست برای HEAD شاخه در این مرحله هنوز ثبت نشده است.

## ۱. سطوح آزمون

| سطح | چه چیزی را می‌سنجد | نمونهٔ تست/منبع |
|---|---|---|
| Unit/contract | allowlist، route resolver، state guard، تبدیل/اعتبارسنجی ورودی | تست‌های `shared/tests/*` |
| Build | خروجی مستقل student/coach/club/marketing/preview و CSS Django | `node build.js` |
| Browser regression | تعامل صفحه، ناوبری، viewport، فرم و پیام | Playwright در `shared/tests/run-all.mjs` |
| Django contract | ساختار HTML، فرم، CSRF، URLها و selectorهای پل | قرارداد handoff و تست‌های backend موجود؛ اجرا فقط روی checkout/commit هماهنگ |
| Visual | سلسله‌مراتب، فاصله، کنتراست، شکست RTL، حالت‌ها | screenshots مقایسه‌ای از baseline و تغییر |
| Package | مانیفست، هش، ساختار ZIP، نصب‌کننده در حالت check | workflow بستهٔ frontend/cPanel |

## ۳. سناریوهای بحرانی محصول

### حساب و نقش
- OTP موفق، کد نامعتبر، کد منقضی، ارسال مجدد، شمارهٔ تکراری، تکمیل ناقص پروفایل.
- نقش‌های student/coach/gym؛ تفاوت role=club در PWA باید جداگانه ثبت شود.
- دسترسی مهمان و مسیر برگشت امن؛ خروج با POST و CSRF.

### فروشگاه و پرداخت
- کاتالوگ خالی؛ محصول بدون تصویر؛ تنوع بدون موجودی؛ قیمت تغییرکرده.
- افزودن/حذف/به‌روزرسانی سبد و محدودیت موجودی از سرور.
- بدون نشانی نباید Checkout نهایی شود.
- قیمت ارسالی مرورگر نادیده گرفته شود؛ هزینهٔ ارسال و جمع نهایی از سرور.
- انتقال به درگاه با redirect بومی؛ callback تکراری idempotent.
- شکست/لغو/timeout نباید به پیام پرداخت موفق تبدیل شود.

### مربی و دوره
- فقط CoachPortfolio منتشرشده عمومی باشد.
- درخواست در انتظار/ردشده/ارسال مجدد خصوصی بماند.
- دورهٔ منتشرنشده در فهرست عمومی نمایش داده نشود.
- قسمت پولی بدون خرید پخش نشود؛ URL stream خصوصی افشا نشود.
- اتمام قسمت و جم نباید دوبار ثبت شود.

### باشگاه فیزیکی
- فقط gym فعال در فهرست عمومی باشد؛ pending عمومی نشود.
- مالک نقش gym به پنل خود دسترسی داشته باشد؛ نقش‌های دیگر منع شوند.
- مربی حساب‌دار و مربی placeholder از هم متمایز شوند.
- نبود endpoint جست‌وجوی جغرافیایی به نقشه/فاصلهٔ ساختگی تبدیل نشود.

### محتوا و قابلیت‌های بدون backend
- فقط Blog منتشرشده قابل مشاهده باشد.
- Tatamipedia و videoهای نمونه با برچسب وضعیت منبع نمایش داده شوند.
- AI/مربی آنلاین بدون سرویس عملیاتی، خروجی تحلیلی واقعی‌نما نمایش ندهند.
- خدمات تخصصی و مسابقات فقط UI-only تا تأیید قرارداد.

## ۴. گیت‌های Build و تست فعلی

فرمان‌های مرجع از پوشهٔ `shared/`:

```bash
npm test
node build.js
node tests/django-bridge.test.mjs
node tests/auth-route-contract.test.mjs
```

این فهرست به معنی اجرای موفق نیست. قبل از شروع تغییر اجرایی باید baseline روی محیطی با Node، Playwright و نسخهٔ هماهنگ Django اجرا و خروجی کامل نگهداری شود.
