# کاتالوگ پوسته‌ها و الگوهای چیدمان تاتامی پلاس

**نسخه:** ۰.۱، مبنا ۲۸ نوامبر ۲۰۲۶  
**اصل طراحی:** پوسته‌ها می‌توانند مشترک باشند، اما صفحه‌ها بر اساس کار کاربر الگوی محتوایی مستقل دارند. هیچ‌کدام از الگوها مجوز ایجاد root رندر دوم نیستند.

## ۱. پوسته‌های محصول

| شناسه | پوسته | سطح/مالک | عناصر مشترک | مرز مهم |
|---|---|---|---|---|
| L-01 | وب عمومی و Preview | `shared/src/index.html` و Router | هدر عمومی، ناوبری، ناحیهٔ `#app`، پیام/Toast، فوتر | Router در اجرای عادی مالک `#app` است |
| L-02 | Preview متصل به Django | پوستهٔ Preview + `django-route-bridge.js` | همان هدر و فوتر؛ محتوای دریافتی از Django | Bridge همان HTML واقعی را در پوسته نمایش می‌دهد؛ Session/CSRF متعلق به Django می‌ماند |
| L-03 | PWA هنرجو | خروجی `dist/student` | پوستهٔ مستقل نصب‌شونده، منوی نقش، داشبورد | دادهٔ حساب/عملیات واقعی فقط با قرارداد معتبر |
| L-04 | PWA مربی | خروجی `dist/coach` | پوستهٔ مستقل، ناوبری مربی، قاب داشبورد | نقش محلی PWA احراز هویت Django نیست |
| L-05 | PWA باشگاه | خروجی `dist/club` | پوستهٔ مستقل و ناوبری فعلی با role=club | نقش Django برابر gym است؛ تا mapping تأییدنشده یکسان فرض نشوند |
| L-06 | پنل بازاریابی | Build مستقل `marketing` | سایدبار ابزار، فضای کار، نوار وضعیت | API JSON فعلی در Django تأیید نشده؛ حالت demo را با production اشتباه نگیرید |

## ۳. قواعد ظرف و شبکه

- ظرف محتوای عادی از `--tp-container-page` استفاده کند؛ خوانایی مقاله با `--tp-container-article` محدود شود.
- `.w` ظرف عمومی و `.d-s` جداساز بخش است؛ الگوهای جدید باید به جای override سراسری، کلاس صفحه داشته باشند.
- شبکه‌های `.pg` و `.grid` موجودند؛ تعداد ستون‌ها براساس حداقل عرض کارت و viewport تعیین شود، نه فقط breakpoint ثابت.
- داشبورد از الگوی sidebar + content مانند `.d-l` استفاده می‌کند؛ در عرض کمتر از ۹۰۰ پیکسل به ناوبری فشرده/قابل دسترس تبدیل شود.
- فاصلهٔ هدر sticky در `scroll-margin` عنوان/بخش لحاظ شود.
- در موبایل ۳۶۰ پیکسل، overflow افقی ناخواسته، جدول، فیلتر و فرم باید تست شوند.

## ۴. قرارداد Header و Navigation

- ناوبری عمومی و ناوبری نقش‌محور نباید در یک منو با لینک‌های غیرمجاز مخلوط شوند.
- مسیر فعال هم از نظر ظاهری و هم با `aria-current`/معادل معنایی مشخص شود.
- منوی موبایل با لمس و صفحه‌کلید قابل باز و بسته‌شدن باشد؛ focus پس از بستن به کنترل مبدأ برگردد.
- لینکِ صفحهٔ فاقد backend می‌تواند به طراحی کامل خود برود، اما label یا وضعیت باید نشان دهد که سرویس عملیاتی در دسترس نیست.
- عدد سبد، جم، تعداد پیام یا شمارنده تنها از منبع معتبر پر شود؛ در غیر این صورت حذف یا placeholder صریح نمایش داده شود.

## ۵. جداسازی پوسته از صفحه

- پوسته فقط ساختار سراسری و نقش‌محور را تعریف می‌کند.
- صفحه مالک محتوای خاص، ترتیب اطلاعات، state و تعاملات خود است.
- یک feature مجاز نیست هدر/فوتر یا `#app` را مستقلاً دوباره render کند.
- صفحات متصل Django از مسیر و HTML سرور می‌آیند؛ CSS باید با selectors پایدار و scopeشده طراحی شود.
- استایل‌های Admin از workflow بومی Django عبور نمی‌کنند و نباید ساختار DOM آن را با فرض ثابت بازنویسی کنند.
