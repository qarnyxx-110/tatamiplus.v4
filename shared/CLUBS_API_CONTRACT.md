# قرارداد اتصال فرانت‌اند فهرست و نقشهٔ باشگاه‌ها

این سند قرارداد مورد انتظار فرانت‌اند برای اتصال صفحهٔ باشگاه‌هاست. این تغییر فقط فرانت‌اند است؛ در این مرحله هیچ مدل، View، URL، API یا جدول دیتابیسی در بک‌اند ساخته یا تغییر داده نشده است.

## تنظیمات عمومی

فایل تنظیمات عمومی در مسیر `shared/public/assets/neshan-config.js` است:

- `TP_CLUBS_JSON_URL`: آدرس endpoint عمومی دریافت فهرست باشگاه‌ها؛ ترجیحاً مسیر هم‌دامنه مانند `/api/v1/clubs/`.
- `TP_NESHAN_WEB_KEY`: کلید Web SDK نشان با محدودیت دامنه. از Service Key استفاده نشود.

تا زمان آماده‌شدن بک‌اند و دریافت کلید معتبر، هر دو مقدار خالی می‌مانند. خالی‌بودن کلید نشان نباید مانع دریافت و نمایش فهرست API شود؛ فقط بخش نقشه/نشانک‌ها غیرفعال می‌ماند.

## درخواست

فرانت‌اند یک درخواست GET به `TP_CLUBS_JSON_URL` می‌فرستد و این پارامترها را در Query String قرار می‌دهد:

| پارامتر | نوع | شرح |
|---|---|---|
| `query` | string | جستجو در نام باشگاه، شهر، مربی و توضیحات |
| `city` | string | نام شهر انتخاب‌شده؛ در حالت انتخاب شهر می‌تواند همراه مختصات نیز ارسال شود |
| `gender` | `men` / `women` | فیلتر گروه هدف |
| `radius_km` | number | یکی از ۲، ۵، ۱۰ یا ۲۵ کیلومتر |
| `lat` | number | عرض جغرافیایی کاربر؛ فقط با مختصات معتبر فرستاده می‌شود |
| `lng` | number | طول جغرافیایی کاربر؛ فقط با مختصات معتبر فرستاده می‌شود |

فیلتر شعاع فقط هنگامی معنا دارد که هر دو پارامتر `lat` و `lng` معتبر باشند. اگر مختصات ارسال نشده باشد، فرانت‌اند فیلتر شعاع را اعمال نمی‌کند. وقتی هم شهر و هم موقعیت کاربر تعیین شده باشند، هر دو شرط باید رعایت شوند.

## پاسخ

فرانت‌اند یکی از دو قالب زیر را می‌پذیرد:

```json
[
  {
    "id": "club-123",
    "name": "نام باشگاه",
    "city": "تهران",
    "coach_name": "نام مربی",
    "description": "توضیح کوتاه",
    "status": "active",
    "gender": "women",
    "student_count": 24,
    "schedule": "شنبه و دوشنبه",
    "latitude": 35.72,
    "longitude": 51.40,
    "detail_url": "/clubs/club-123/"
  }
]
```

یا:

```json
{
  "results": [
    {
      "id": "club-123",
      "name": "نام باشگاه",
      "city": "تهران",
      "gender": "both",
      "latitude": 35.72,
      "longitude": 51.40
    }
  ]
}
```

پاسخ باید فهرست کامل رکوردهای متناسب با فیلترها را در یک آرایهٔ `results` یا آرایهٔ مستقیم برگرداند؛ فرانت‌اند در این نسخه صفحه‌بندی پاسخ API را پیاده‌سازی نکرده است. فرانت‌اند فیلترها را دوباره روی پاسخ اعمال می‌کند تا کارت‌ها و نشانک‌های نقشه از یک مجموعهٔ یکسان ساخته شوند.

## فیلدها و اعتبارسنجی

| فیلد | وضعیت | نام‌های جایگزین پذیرفته‌شده |
|---|---|---|
| `id` | اجباری، غیرخالی و یکتا | `slug` |
| `name` | اجباری و غیرخالی | `title` |
| `city` | اختیاری | — |
| `coach_name` | اختیاری | `coachName` یا `coach` (رشته یا شیء دارای `name`) |
| `description` | اختیاری | `summary` |
| `status` | اختیاری | `status_label` |
| `gender` | اختیاری | `target_gender` یا `audience` |
| `student_count` | اختیاری و عددی | `students_count` |
| `schedule` | اختیاری | `schedule_text` |
| `latitude` و `longitude` | اختیاری؛ باید هر دو و در محدوده جغرافیایی معتبر باشند | `lat` و `lng` |
| `detail_url` | اختیاری | `url` |

مقادیر متعارف جنسیت: `men`، `women`، `both`. مقادیر فارسی «آقایان»، «بانوان» و «آقایان و بانوان» نیز پذیرفته می‌شوند. رکورد با جنسیت نامشخص در فیلتر مردان/زنان قرار نمی‌گیرد.

وضعیت‌های متعارف: `active`، `inactive`، `registration_open`، `pending`؛ برچسب‌های فارسی متناظر هم پذیرفته می‌شوند.

رکورد فاقد شناسه یا نام، و شناسهٔ تکراری، از نمایش حذف می‌شود. رکورد بدون مختصات معتبر می‌تواند در فهرست و کارت باقی بماند، اما نشانک نقشه نمی‌گیرد؛ هنگام فیلتر شعاعی، رکورد بدون مختصات قابل ارزیابی نیست و در نتیجهٔ شعاعی قرار نمی‌گیرد.

`detail_url` فقط در صورت معتبر بودن URL امن نمایش داده می‌شود. فرانت‌اند برای شناسه‌های API مسیر جزئیات ساختگی تولید نمی‌کند. این پروژه در حال حاضر مسیر جزئیات باشگاه را با شناسهٔ عددی نمونه نمایش می‌دهد؛ مسیر واقعی جزئیات باید از سمت بک‌اند و با هماهنگی ارائه شود.

## رفتار خطا و کلید نقشه

- پاسخ غیرموفق HTTP، JSON نامعتبر یا ساختار پاسخ نامعتبر، به‌عنوان خطای دریافت فهرست نمایش داده می‌شود؛ دادهٔ نمونه به‌عنوان جایگزین پنهانی نمایش داده نمی‌شود.
- اگر فهرست API موفق باشد ولی Web Key موجود نباشد، کارت‌ها و فیلترهای داده‌ای کار می‌کنند و فقط نشانک‌های نقشه نمایش داده نمی‌شوند.
- اگر SDK نقشه بارگذاری نشود، فهرست API حفظ می‌شود و فقط وضعیت خطای نقشه اعلام می‌شود.
- مختصات نباید از نام شهر، مرکز استان یا دادهٔ حدسی ساخته شوند.
- endpoint هم‌دامنه پیشنهاد می‌شود. در صورت cross-origin بودن، بک‌اند باید CORS مناسب را تنظیم کند.

## محدودهٔ این تغییر فرانت‌اند

این قرارداد به‌معنای پیاده‌سازی endpoint در سرور نیست. تا وقتی بک‌اند endpoint و داده‌های واقعی (به‌ویژه مختصات و جنسیت هدف) را ارائه نکند، صفحهٔ Preview از شش رکورد نمونهٔ موجود استفاده می‌کند؛ گزینه‌های جنسیت، شعاع و «نزدیک من» در حالت نمونه غیرفعال می‌مانند و نقشه نشانک جعلی نشان نمی‌دهد.
