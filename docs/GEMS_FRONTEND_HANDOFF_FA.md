# تحویل فرانت‌اند رابط جم (Gem UI)

## خروجی‌ها

- `django/templates/components/gem_badge.html`: نشان قابل‌استفادهٔ مجدد موجودی جم در هدر.
- `django/templates/account/gems.html`: صفحهٔ موجودی و تاریخچهٔ تراکنش‌ها.
- `shared/src/js/shared/views-new.js`: صفحهٔ نمایشی تاریخچه در Preview عمومی با مسیر `#/gems`.
- `shared/src/index.html` و `shared/src/css/ui.css`: نشان موجودی در هدر Preview و استایل‌های مشترک.
- `shared/src/js/shared/router.js`, `shared/src/js/shared/core.js`, `shared/build.js`: مسیر و لینک منو.
- `django/static/js/tatami.js`: نمایش کوتاه پیام‌های Django با تگ `gem` به‌شکل toast.

## قرارداد پیشنهادی context

صفحهٔ `account/gems.html` به این متغیرها نیاز دارد:

| متغیر | نوع/ساختار | توضیح |
|---|---|---|
| `gem_balance` | عدد | موجودی فعلی کاربر؛ در header نیز استفاده می‌شود. |
| `transactions` | iterable | تراکنش‌های مرتب‌شده از جدید به قدیم. |
| `gem_help_text` | رشته، اختیاری | توضیح روش‌های دریافت و مصرف جم که باید از بک‌اند/تنظیمات بیاید. |

هر تراکنش باید فیلدهای زیر را داشته باشد:

| فیلد | توضیح |
|---|---|
| `date_shamsi` | تاریخ از قبل به تقویم شمسی قالب‌بندی شده باشد. |
| `reason` | دلیل تراکنش؛ متن از داده بیاید، نه هاردکد فرانت‌اند. |
| `amount` | مقدار مثبت عددی/قدر مطلق تراکنش. |
| `is_credit` | مقدار بولی؛ true برای افزایش و false برای مصرف. |

## قرارداد URL پیشنهادی

در نشان هدر از نام مسیر `account:gems` استفاده شده است. این نام باید با توسعه‌دهندهٔ بک‌اند هماهنگ و در URLConf ثبت شود. اگر نام قطعی متفاوت است، فقط همین قرارداد URL در قالب badge تغییر کند.

## اعلان دریافت جم

view بک‌اند هنگام ایجاد تراکنش مثبت می‌تواند Django message را با تگ `gem` ثبت کند؛ مثلاً:

```python
messages.success(request, message_text, extra_tags="gem")
```

متن پیام باید از رویداد/منطق تأییدشدهٔ بک‌اند بیاید. جاوااسکریپت فقط پیام دارای تگ `gem` را به toast کوتاه تبدیل می‌کند؛ خودش پاداش یا مقدار جم تولید نمی‌کند.

## مرزهای مسئولیت و موارد تأییدنشده

- این تغییرات فقط فرانت‌اند هستند؛ مدل تراکنش، موجودی، context processor، view، URLConf، قوانین کسب/مصرف و دیتابیس تغییر نمی‌کنند.
- مقدار موجودی، دلیل تراکنش، پاداش‌ها و قیمت‌گذاری جم از فرانت‌اند ساخته نمی‌شوند.
- قوانین دقیق جم در سند کارفرما نهایی نشده‌اند؛ هیچ toggle خرج جم در Checkout یا فرمول تبدیل اضافه نشده است.
- Preview استاتیک در `#/gems` عمداً موجودی را با خط تیره و تاریخچه را خالی نمایش می‌دهد تا دادهٔ ساختگی به‌عنوان موجودی واقعی برداشت نشود.
- برای نمایش واقعی در Django، بک‌اند باید context و URL فوق را فراهم کند.
