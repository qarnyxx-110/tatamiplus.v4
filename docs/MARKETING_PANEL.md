# پنل مارکتینگ (مدیریت مقاله‌ها و تاتامی‌پدیا)

**خروجی جدا:** `marketing/` — از سه PWA هنرجو/مربی/باشگاه جدا است و هیچ کد مدیریتی در آن‌ها نیست (آزمایش‌شده: Build سه PWA شامل کد پنل نیست). تاتامی‌پدیا زیرمجموعه همین پنل است («تاتامی‌پدیا» و «دسته‌های تاتامی‌پدیا» در منو).

## دو حالت (هنگام Build)
| حالت | شرایط | معنی |
|---|---|---|
| **API** | `TP_API_BASE=/api/v1 node build.js` | به بک‌اند شما وصل می‌شود (قرارداد: `API_CONTRACT.md`). مجوزها فقط در بک‌اند معتبرند. |
| **نمایشی** | بدون `TP_API_BASE` | داده فقط در `localStorage` همان مرورگر؛ ورود نمایشی بدون احراز هویت؛ **به سایت عمومی وصل نیست** و عملیاتی نیست. بنر زرد دائمی هشدار می‌دهد. |

## قابلیت‌ها (رابط)
فهرست مقالات با جست‌وجو/فیلتر وضعیت و دسته/صفحه‌بندی؛ ایجاد/ویرایش (عنوان، slug یکتا با تولید خودکار، خلاصه، نویسنده، دسته، برچسب، تصویر شاخص، سئو با شمارنده)؛ ویرایشگر متن غنی (تیتر ۲/۳، پررنگ/کج، فهرست، نقل‌قول، پیوند، تصویر، پاک‌کردن قالب؛ چسباندن پاک‌سازی می‌شود)؛ ذخیره پیش‌نویس؛ پیش‌نمایش؛ انتشار/لغو انتشار؛ زمان‌بندی (اعمال با بک‌اند)؛ حذف با تأیید؛ اعتبارسنجی تصویر (JPEG/PNG/WebP ≤ ۲MB، سمت کلاینت و باید سمت سرور هم باشد). اصطلاحات: ایجاد/ویرایش/حذف، دسته‌بندی، پیش‌نویس/انتشار، اصطلاح پرکاربرد، مرتبط‌ها، تصویر اختیاری؛ مدیریت دسته‌ها.

## حساب مارکتینگ
حساب را **در بک‌اند** بسازید (Group با مجوزهای `articles.*`, `glossary.*`, `media.upload` و `is_staff=False`). این پروژه حساب نمی‌سازد. برای تست، سرور آزمایشی کاربران `marketing / editor / student` دارد (فقط ابزار تست).

## وبلاگ و تاتامی‌پدیا عمومی
با `TP_API_BASE` فهرست‌ها از API خوانده می‌شوند (TTL ۶۰ ثانیه)؛ اگر API در دسترس نباشد داده نمونه محلی نمایش داده می‌شود و هشدار می‌دهد. آدرس مقاله: `#/blog/<slug>` (شناسه عددی داده نمونه برای سازگاری پذیرفته می‌شود). صفحه‌بندی ۶ مقاله در صفحه (کلاینتی؛ در حالت API حداکثر ۱۰۰ مقاله اول دریافت می‌شود).

## محدودیت‌ها
ویرایشگر مبتنی بر `contenteditable/execCommand` است (منسوخ ولی کارا)؛ برای محصول نهایی ویرایشگر کتابخانه‌ای پیشنهاد می‌شود. کتابخانه رسانه (فهرست تصاویر بارگذاری‌شده) پیاده‌سازی نشده. زمان‌بندی و مجوزها بدون بک‌اند واقعی عملیاتی نیستند. در حالت نمایشی تصویر به Data-URL فشرده در localStorage ذخیره می‌شود. تست واقعی با Django انجام نشده؛ فقط با سرور آزمایشی.
